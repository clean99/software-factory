# Plugins and adapters

Enumerate source types and optional fields, then the target slots and actual receiving handler. Record type × field × direction as preserved, lost or no-slot. A deliberately lossy conversion or absent server support is not a missing-field bug. Test producer → converter → consumer, not only a mocked transport.

Read merged sibling fixes for conventions, not proof of new demand. Once a second sibling shows the same defect class, audit all siblings and record a coverage table in validation.md, including untouched/unsupported paths.

For config-driven tools, compare base and head on a corpus of real public configs before review. Cover every input channel: config formats, package.json, CLI flags and dotted overrides, extends, hook-module resolution. Show no new false positives or crashes; explain legitimate no-delta cases. If existing helpers cannot reproduce the tool's loader, limit the plugin to config discovery.

Use pinned upstream discovery source, not a remembered layout. Match tests to ordinary repository granularity, not a huge synthetic suite. For streams vary chunk boundaries and accumulated input, not just one complete chunk.

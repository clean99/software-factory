# PR text

Choose the title convention from recent git subjects and title CI. Usually 5–15 body lines suffice; never cut required template fields to meet that target.

Lead with the observable old behavior and documented contract, then the smallest fix, exact regression command and unchanged neighboring inputs. Include a runnable reproduction on the exact version, preferably through public exports; concrete input beats quality claims.

Write plainly: no “This PR aims to”, “comprehensive”, “robust”, “seamless”, decorative formatting, trivia lists or closing summary. Use the repository's issue-closing convention. Local screenshot paths will not render on GitHub.

When maintainers reject scope, say exactly what was removed and kept. Give the coordinator a ready-to-post reply, not process commentary. A maintainer should understand a small PR in two minutes and a large one in ten.

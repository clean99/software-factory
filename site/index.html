Software Factory · an agent pipeline for open-source contributionsDesigned and run by clean99

Agents write the fix.01the work Code decides what ships.02the decision Maintainers keep score.03the verdict

Software Factory is a pipeline of AI agents that contributes fixes to other people's open-source projects. It starts from a problem a user reported, writes the fix with a test that fails without it, has a second agent try to break it, and opens the pull request.

No person reviews each pull request. A command-line gate refuses any push whose reviews and approval do not match the exact commit. What maintainers then do with it is recorded here, closures and silence included.

Sheet 02Mechanisms

What it does, and where to check

Six mechanisms in the repository, each with the number it has produced so far.

ItemMechanismWhat it doesOn record
  1. A

    Picks work someone asked for

    A candidate must name who hits the problem, with a source. The CLI reads the issue's live state, and an agent that did not propose the candidate decides whether to build it, propose it to the maintainers first, or drop it.

    63of 192 recorded candidates stopped before a pull request.
    value-review role →

  2. B

    Proves the fix before review

    The implementer shows its regression test failing on the old commit and passing on the new one. Proof commands run through the CLI, which signs a receipt: the command, its exit status, an output hash and the commits.

    497signed receipts on record.
    how receipts work →

  3. C

    Reviews with a second agent

    The reviewer did not write the change. It answers a fixed list of risk classes, the ways earlier changes failed, each with a receipt or the reason it does not apply. A second failed round ends in takeover or the shelf, not a third try.

    44candidates sent back at least once before anything shipped.
    risk classes →

  4. D

    Lets code decide what ships

    The next action is computed from files, receipts and saved GitHub state, so a session that loses its context cannot skip a step. The release gate refuses a push when any review or approval no longer matches the commit, and scans everything outbound.

    1,755tests on the factory's own code.
    tests →

  5. E

    Says what it is

    From 2026-11-20 each new pull request ends with a line saying this pipeline prepared it. Projects that ban or restrict AI contributions are not candidates, and a maintainer can take a project off the list with one issue.

    25of the 129 descriptions written before that date disclosed AI use; 104 did not.
    for maintainers →

  6. F

    Changes when it is wrong

    Every closure and every rework gets one recorded reason, and most reasons name the station that should have caught it. The reason becomes a lesson routed to that role, a check in the gate, or a past case a model must read correctly before it is given a role.

    8recorded changes, each tied to the failure behind it.

No change request, no fix pushed after opening, no repair by a maintainer. The factory's build and review decide this, along with how strictly each project reviews.
